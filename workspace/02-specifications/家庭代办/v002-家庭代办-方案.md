# 家庭代办 产品需求文档 v002

状态：draft。本版相对 v001 的核心变更是数据存储与媒体能力。视觉与主流程仍以前确认的 v001 / 原型 v003 为基线。

产品暂名 LuckyTodo。

## 1. 需求目标

做一个安装在家庭 iPhone 上的待办应用，让夫妻、孩子和父母把便签、待办、日程和周期计划放在同一家庭空间里，并督促执行。

本版数据目标：

1. **可以离线使用。** 断网时仍能查看和编辑本机已有权限的内容；新建、修改、打卡、附件先落在本机。
2. **登录并联网后多端同步。** 同一账号在多台 iPhone 上使用时，与飞牛 NAS 上的家庭服务双向同步。
3. **多账号数据关联。** 同一家庭内不同成员账号，按角色权限共享、指派、查看彼此关联的数据（例如多人计划、指定可见便签、家长查看孩子打卡）。
4. **个人头像可上传。** 在「我的」里用相册或拍照设置自己的头像。
5. **事项可加照片或附件。** 便签、待办、日程、计划都支持添加图片和其它附件。

部署与安装前提不变：服务在飞牛 fnOS 的 Docker 中；应用填写已有 HTTPS 地址；IPA 用全能签签名安装；提醒仍以本机本地通知为主。

## 2. 背景与用户痛点

家庭事项不能只依赖「在线时才能记」。出门、信号差、NAS 临时不可达时，也要能先记下待办和打卡。家里又有多台 iPhone，同一个人换手机、配偶和孩子各自登录后，仍需要同一套家庭数据对齐。

v001 以「服务器为准、离线只读会话」为假设，无法满足上述场景。本版改为 **本机优先写入 + 联网后与 NAS 同步**，并把头像、附件纳入家庭媒体库。

## 3. 用户角色与核心场景

角色定义沿用 v001：管理员、家长、成人、儿童。一套服务只服务这一个家庭。

新增或强化的场景：

1. **离线记下待办。** 林晨在地铁里新建「买牛奶」，附一张货架照片。本机立刻可见。回家连上 HTTPS 后，待办与照片自动上传到飞牛，周宁的手机随后同步到。
2. **同一账号多端。** 林晨的 iPhone 和备用机都登录同一账号。任意一端勾选完成，另一端联网后状态一致。
3. **多账号关联。** 周宁创建「每天阅读」并指定林小满。林小满账号打卡后，林晨、周宁账号都能在各自权限范围内看到该计划的执行记录与反馈。私人便签仍按可见范围隔离。
4. **更换头像。** 林小满在「我的」上传学校照片。上传成功后，计划详情、成员列表等展示新头像；其它已登录设备联网后更新。
5. **计划带附件。** 家长在计划说明里附上阅读清单 PDF 或示例照片，执行人打开计划即可查看或下载到本机缓存。

## 4. 需求范围

继承 v001 的功能范围，并增加：

- 本机持久化数据库与媒体缓存；断网可读写。
- 登录账号联网后的增量同步、冲突处理、同步状态展示。
- 家庭空间内多成员账号的数据关联（已有指派 / 可见性 / 家长查看规则，本版明确作为同步模型的一部分）。
- 个人头像：拍照或相册选择、裁剪为正方形、上传、删除恢复默认。
- 便签、待办、日程、计划的照片与附件：添加、预览、删除、离线排队上传。
- 飞牛侧除 API 与 SQLite 外，增加对象媒体存储目录（头像与附件文件）。

原型阶段已演示的 AI 洞察页，本版文档记为 **可选增强能力**：基于本机已同步数据做分析，不上传到家庭以外的服务。实现排期可后于离线同步与附件。

## 5. 非目标范围

- Android、手表、桌面端；iPad 专用分栏。
- App Store / TestFlight / 苹果远程推送。
- 逾期再提醒、对过去周期补卡。
- 语音录制留言、家庭群聊、积分商城。
- 多个互不相干的家庭共用一套账号体系。
- 实时协作光标、OT/CRDT 级别的字符同步。本版事项级同步即可。
- 将家庭数据同步到第三方云盘或公有云 AI。
- 绕过 iOS 签名验证。

## 6. 产品架构

```text
iPhone A / iPhone B（可同一账号或不同家庭成员账号）
  ├─ 本地库（事项、执行记录、同步队列、会话）
  ├─ 本地媒体缓存（头像、附件原图或缩略图）
  └─ 本地通知登记
        │  HTTPS，可断可续
        ▼
飞牛 fnOS
  Docker Compose
    ├── luckytodo-api
    │     └── SQLite（元数据、权限、同步版本）
    └── media 卷
          ├── avatars/
          └── attachments/
```

### 6.1 本机优先写入

- 用户操作（新建 / 编辑 / 删除 / 打卡 / 改头像 / 加附件）先写入本机库，界面立即更新。
- 每条变更进入同步队列，状态为：待上传 / 上传中 / 已同步 / 失败可重试。
- 未登录时：数据只存在本机，标记为「本机访客数据」。登录同一家庭账号后，询问是否合并进该账号（见 11）。

### 6.2 联网同步

- 健康检查通过且会话有效时，客户端按「推送本机队列 → 拉取服务器增量」循环。
- 增量依据每条记录的 `updatedAt` 与单调 `revision`（服务器分配）。
- 媒体文件在元数据同步成功后按需上传或下载；列表优先显示缩略图。
- 同步失败不回滚本机已展示的结果，只标记失败并可手动「立即同步」。

### 6.3 多账号关联

- 服务器以「家庭」为租户。所有成员账号属于同一 `familyId`。
- 关联关系包括：执行人、参与人、便签可见成员、计划创建人与执行人、家长对儿童计划的只读监督。
- 同步拉取时，只下发当前账号 **有权看见** 的对象与附件元数据。无权对象不会因多端同步泄露。

## 7. 使用流程

### 7.1 离线使用

1. 已登录用户打开应用，即使无检查失败，仍进入「今天」，顶部显示「离线，变更会在联网后同步」。
2. 用户新建待办、打卡、添加照片。本机立刻可见；附件显示「待上传」。
3. 网络恢复后自动同步；成功后「待上传」消失。其它已登录设备随后拉到变更。

### 7.2 多端同步

1. 账号在设备 A、设备 B 均已登录并填过同一服务器地址。
2. 设备 A 修改一条计划说明并保存。
3. 设备 B 在前台或下次进入前台时拉取增量，列表与详情更新为同一内容。
4. 若两端在离线时改了同一条记录，采用 11 节冲突规则。

### 7.3 设置头像

1. 进入「我的」→ 点击头像 → 选择「拍照」或「从相册选择」。
2. 进入正方形裁剪，确认后本机立即显示新头像，状态「同步中」。
3. 上传到 `avatars/{memberId}` 成功后，家庭内其它有权看到该成员的界面在同步后更新。
4. 「恢复默认」删除自定义头像文件，界面回到姓名首字头像。

### 7.4 给事项加附件

1. 在便签 / 待办 / 日程 / 计划的新建或编辑页，点击「添加照片或附件」。
2. 可选：拍照、相册、文件（系统文件选择器）。
3. 选中后显示缩略图或文件名；可删除尚未保存或已保存的附件（需确认）。
4. 保存事项后，附件随事项同步；离线时先本地缓存。

其余主流程（创建家庭、登录、今天、日历、计划打卡等）沿用 v001，仅增加离线横幅与同步入口。

## 8. 产品风格与功能布局

沿用已确认视觉方向（待办清单 + 可切换皮肤；原型 v003 的夜航风格可作为实现参考）。

本版 UI 增量：

- 「我的」头像可点，右下角小相机标识。
- 各编辑页增加附件区：横向缩略图条 +「添加」。
- 「我的」或「今天」下拉可触发同步；「我的」展示最近同步时间与失败条数。
- 离线横幅可关闭至下次冷启动，但不隐藏同步失败入口。

## 9. 功能明细与交互逻辑

### 9.1 离线与同步状态

| 状态 | 界面 |
|------|------|
| 在线且队列为空 | 无横幅；「我的」显示「已同步 · HH:mm」 |
| 在线且队列非空 | 「我的」显示「同步中（N）」；可点「立即同步」 |
| 离线 | 顶部横幅「离线，变更会在联网后同步」 |
| 单项失败 | 该条详情或附件上显示「同步失败」，提供「重试」 |
| 会话过期 | 可继续离线浏览本机缓存；写操作仍写入本机，但提示「重新登录后才能同步到家庭」 |

下拉刷新在离线时只刷新本机查询，并 Toast「当前离线」。

### 9.2 头像

- 仅本人可改自己的头像。管理员不能代传儿童头像以外的他人头像；**可以为儿童代设头像**（儿童账号由家长管理）。
- 输出正方形，建议长边 512px，JPEG/HEIC 转存为 JPEG。
- 列表与详情使用圆形裁切展示；加载失败回退姓名首字。
- 头像文件权限：家庭成员可见该成员头像（用于执行人列表等），不单独做「隐藏头像」。

### 9.3 附件

适用于：便签、待办、日程、计划（含计划说明；打卡反馈本版仍以文字为主，反馈暂不强制附件，但待办/计划对象本身可带附件）。

| 规则 | 取值 |
|------|------|
| 单条对象附件数 | 最多 9 个 |
| 图片 | jpg / jpeg / png / heic / webp，单文件 ≤ 10MB |
| 其它附件 | pdf / txt / doc / docx / xls / xlsx / zip，单文件 ≤ 20MB |
| 超限 | 选择后立即提示，不加入列表 |
| 预览 | 图片进全屏滑动预览；其它文件用系统分享/打开 |
| 删除 | 需确认「删除这个附件？」；已同步的删除会进入同步队列 |
| 权限 | 能看见该事项的人，才能看见并下载其附件 |

离线添加的附件在队列中标记 `localUri`；上传成功后改为服务器 `mediaId`，本机可保留缓存。

### 9.4 多端与多账号

- 同一 `username` 允许最多 **5** 台活跃设备会话；超出时踢掉最久未用的会话，并在被踢设备提示重新登录。
- 不同成员账号之间不共享登录态；只通过家庭数据关联。
- 儿童账号的同步范围仅限其可见数据；家长账号同步包含其监督所需的儿童计划记录。

### 9.5 与 v001 页面的衔接

连接、登录、今天、日历、计划、便签、打卡、成员管理等行为保持 v001 规则，差异仅在于：

- 保存成功不再要求「必须请求服务器成功」；改为「已保存到本机」，联网后再变「已同步」。
- 删除、归档同样先本地生效。
- 「模拟连不上」类调试能力在工程上对应真实离线队列，而不是整页不可用。

## 11. 状态、规则与异常处理

| 场景 | 处理 |
|------|------|
| 两端离线改同一条事项 | 以 `updatedAt` 较新者胜出（LWW）；落败方的附件若未冲突则尽量保留并入胜出版本 |
| 一端删、一端改 | 删除的 `deletedAt` 更新时间更晚则删除生效；否则恢复为修改版并取消删除 |
| 附件上传失败 | 事项元数据可先同步；附件保持待上传，不阻断列表 |
| 磁盘空间不足 | 禁止再缓存大附件，提示清理；事项文字仍可保存 |
| 未登录本地数据遇上首次登录 | 弹窗：「把本机 N 条记录合并到当前账号？」合并 / 保留在本机不合并 / 清空本机访客数据 |
| 换了服务器地址 | 警告「将停止与旧服务器同步」；本机数据不清空，但标记为不可向旧服推送，直至用户确认 |
| 儿童上传头像 | 允许；家长也可代设 |
| 无权限的附件链接 | 不展示；深链打开提示无权限 |

媒体与元数据都只存在家庭 NAS 与用户设备，不经过第三方对象存储。

## 13. 验收标准

- [ ] 打开飞行模式后，已登录用户仍能浏览缓存，并能新建待办、打卡；恢复网络后数据出现在服务器与其它设备。
- [ ] 同一账号两台设备，任一端修改标题，另一端联网后看到相同标题。
- [ ] 家长创建的多人计划，孩子账号打卡后，家长账号同步可见该孩子的完成状态与反馈。
- [ ] 成人账号同步后仍看不到儿童私人便签与不应看见的儿童计划。
- [ ] 用户可设置头像；其它成员列表与计划执行人处显示新头像（联网同步后）。
- [ ] 便签 / 待办 / 日程 / 计划均可添加图片或文件；离线添加后显示待上传，联网后可预览。
- [ ] 附件超过数量或大小限制时有明确错误，且不写入。
- [ ] 同步失败有重试入口，不会造成空白死页。
- [ ] 删除附件或恢复默认头像后，其它端同步后一致。

## 14. 待确认问题

1. 附件大小上限是否采用本文默认（图片 10MB / 其它 20MB / 最多 9 个）。
2. 未登录时的本机数据，登录后默认「提示合并」是否符合预期。
3. AI 洞察是否纳入下一版实现，还是继续仅作原型演示。
