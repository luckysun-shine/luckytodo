# 家庭代办 产品需求文档 v001

状态：draft。确认本说明书没有问题之前，不生成原型。

产品暂名 LuckyTodo。正式名称仍可改，不影响本版信息架构。

## 1. 需求目标

做一个安装在家庭 iPhone 上的待办应用，让夫妻、孩子和父母把便签、待办、日程和周期计划放在同一套家庭数据里。一个计划可以指定多名家人执行，每人单独打卡、单独留一句反馈，发起的家长能看到每个人这一周期做了没有。

数据和服务放在飞牛 fnOS 上。家人打开应用后填写家里已经准备好的 HTTPS 地址。应用打包成 IPA，用全能签签名后安装。

## 2. 背景与用户痛点

家庭事项经常留在聊天记录里：买菜、接送、阅读打卡、谁该做家务。聊完就沉下去，过了周期也看不出谁做了、谁没做。

公共待办工具要么只适合一个人勾选，要么要把家庭日常交到别人的服务器上。这个家庭希望数据留在自己的飞牛 NAS 上，手机只作为操作和本地提醒的终端。

长辈和孩子都要能用。主路径保持待办清单的直接感：打开就能看到今天要打卡和要勾选的事，三步内完成打卡。酷炫感来自深色默认皮肤、进度和勾选反馈，而不是多层菜单。

## 3. 用户角色与核心场景

一套服务只服务这一个家庭。成员角色在创建账号时指定。

| 角色 | 谁来当 | 能做什么 |
|------|--------|----------|
| 管理员 | 第一个创建家庭的人，同时具备家长能力 | 创建和解停成员、重置密码、修改家庭时区显示、归档任何计划 |
| 家长 | 需要督促孩子的成年人，通常是夫妻双方 | 给任何成员派待办、日程和计划；查看所有儿童的计划完成情况 |
| 成人 | 不需要看孩子打卡的家人，例如祖辈 | 管理自己的内容；只能把其他成人或自己设为执行人 |
| 儿童 | 由管理员创建的孩子账号 | 只看自己的便签、待办，以及指定给自己的日程和计划；只能给自己建便签和待办 |

核心场景：

1. 家长创建一个「每天阅读」计划，执行人是孩子和自己，提醒时间 20:00。孩子晚上打卡并写一句反馈，家长在计划页看到两个人各自的状态。
2. 任一成员随手写便签。默认只有自己能看。需要配偶知道时，再指定给对方，或一键转成待办。
3. 家长在日历上放入一段时间的日程，例如家长会，并在开始前响一次。
4. 出门后，手机通过已有的 HTTPS 域名连回飞牛，同步新的事项。已经登记在这台手机上的本地通知，到点会响一次。

原型和界面文案使用虚构示例家庭，不代表真实家庭成员：林晨（管理员）、周宁（家长）、林秀兰（成人）、林小满（儿童）。

## 4. 需求范围

- 填写 HTTPS 服务器地址并连接飞牛上的服务。
- 首位用户创建家庭和管理员账号；管理员创建其他成员。没有公开注册。
- 便签、待办、日程、计划四种对象。
- 日历月视图，按天汇总日程、待办和计划。
- 每条提醒只响一次，使用 iPhone 本地通知。
- 计划周期：每天、每周指定星期、每月 1–28 日中的一天、每 N 天（2–30）。
- 多名执行人各自打卡、各自统计，计划详情展示全员当前周期进度。
- 完成打卡时可留下不超过 100 字的反馈。
- 家长查看儿童的计划完成情况，看不到儿童的私人便签。
- 三套皮肤和两档字号，布局不变。
- 飞牛 fnOS 上用 Docker Compose 运行一个 API 服务，数据放在持久化目录中的 SQLite。

## 5. 非目标范围

- Android、iPad 专用布局、手表、桌面端。iPad 若打开，沿用 iPhone 布局拉长，不做分栏。
- App Store 上架、TestFlight、苹果远程推送。
- 逾期后再提醒一次，以及对过去周期补卡。
- 照片、语音、附件、评论区和家庭群聊。
- 奖励、积分、排行榜。
- 多个家庭共用一套账号，或家庭之间互访。
- 儿童自行注册，邮箱或短信验证。
- 学龄前专用的大插画界面。
- 离线新建和离线修改。认证信息、服务器地址、皮肤和字号保存在本机；事项内容以服务器为准。
- 绕过 iOS 签名验证。证书失效后的处理是重新签名安装，再打开应用重新同步。

## 6. 产品架构

```text
iPhone 上的 LuckyTodo
  登录态、皮肤、字号、服务器地址保存在本机
  本地通知由系统持有，应用在每次同步成功后重新登记
        │  仅 HTTPS
        ▼
已有域名和反向代理
        │
        ▼
飞牛 fnOS
  Docker Compose
    └── luckytodo-api
          └── SQLite 文件（映射到飞牛持久化目录）
```

飞牛 fnOS 自带 Docker 与 Compose。第一版交付一个 Compose 项目：单个 API 容器，数据库文件放在卷里。容器监听内网端口。HTTPS 使用家里已经配好的反向代理，不在应用里再做一套证书。

应用保存的服务器地址是这个 HTTPS 源站，例如 `https://todo.家庭域名`。所有接口都在该地址之下。连接前请求健康检查。健康检查返回服务名和家庭是否已初始化。

账号密码只提交给这个家庭服务器。服务端保存密码哈希。登录成功后签发 30 天会话，退出或重置密码后会话失效。

同一家庭的并发很小。内容冲突采用后写覆盖，以服务器收到的更新时间为准。

## 7. 使用流程

### 7.1 第一次把家庭建起来

1. 安装并打开应用，输入 HTTPS 地址，点击「连接」。
2. 健康检查发现家庭尚未初始化，进入「创建家庭」。
3. 填写家庭名称、自己的显示名、用户名和密码。时区固定为中国标准时间，页面上直接写明，不可改。
4. 创建成功后进入「今天」。这时还没有任何事项。
5. 从「我的」进入「成员」，为配偶创建家长账号，为孩子创建儿童账号，为其他家人创建成人或家长账号，并把初始密码当面交给对方。

### 7.2 其他成员登录

1. 打开应用，确认服务器地址后连接。
2. 家庭已初始化，进入登录页。
3. 输入管理员发给自己的用户名和密码。
4. 进入「今天」，只看到自己有权查看的内容。

### 7.3 家长安排一个多人计划并跟踪

1. 在「今天」点击加号，选择「计划」。
2. 填写标题，选择「每天」，设置开始日期和每天提醒时间，勾选孩子和自己。
3. 保存后，两人的「今天」和「计划」里都出现该计划。两人的手机在下一次同步成功后，各自登记当天的本地通知。
4. 到点手机响一次。执行人打开计划，点击「完成打卡」，可以写一句反馈。
5. 家长打开计划详情，看到每个执行人在本周期是待执行、已完成还是缺卡。孩子的私人便签不会出现在这里。

### 7.4 记下一条便签并转成待办

1. 打开「便签」，新建一条。可见范围默认「仅自己」。
2. 若要交给自己去办，选择「转为待办」，补上截止时间和一次提醒。
3. 原便签保留，并显示「已关联待办」。待办出现在对应日期的日历和到期当天的「今天」里。

### 7.5 换皮肤

在「我的」里点选「夜航」「日间清晰」或「暖纸」，并切换「标准」或「大」字号。选择后立即生效，不影响列表结构和底部导航。

## 8. 产品风格与功能布局

整体是单手可操作的待办清单，不是后台管理系统。

- 底部四个固定入口：今天、日历、计划、便签。选中项使用当前皮肤的强调色，并显示文字。
- 「我的」放在「今天」右上角的头像按钮里，不占用第五个底部入口。
- 新建使用右下角加号。成人和家长的菜单是便签、待办、日程、计划。儿童的菜单只有便签、待办。
- 「今天」用分组清单，组与组之间留白。计划详情里的「本周期」用一张卡片列出全员，其余历史用清单。
- 勾选或打卡成功时，该行状态在 200 毫秒内变为完成，并出现一句短提示。不做全屏庆祝动画。
- 主按钮每屏最多一个。危险操作使用确认对话框，确认按钮标明具体动作，例如「归档计划」。

字号：

| 档位 | 表现 |
|------|------|
| 标准 | 列表标题约 17pt，辅助文字约 13pt |
| 大 | 同一套文字约为标准的 1.2 倍，列表行高随之增加 |

儿童账号默认「大」。其他角色默认「标准」。默认皮肤都是「夜航」。

三套皮肤只换颜色，不换布局、图标形状和字体家族。

| 皮肤 | 背景 | 卡片 | 主文字 | 次文字 | 强调 | 完成 | 缺卡 |
|------|------|------|--------|--------|------|------|------|
| 夜航 | `#0E1116` | `#171C25` | `#F4F7FB` | `#9AA4B2` | `#6D5EF7` | `#3DDC97` | `#FF5D73` |
| 日间清晰 | `#F5F7FB` | `#FFFFFF` | `#12141A` | `#5C6570` | `#3B5BDB` | `#0E9F6E` | `#E03131` |
| 暖纸 | `#F6F0E6` | `#FFFBF5` | `#2C2416` | `#7A6A58` | `#C46B3A` | `#2F7D4A` | `#B42318` |

状态不只靠颜色区分。完成、缺卡、待执行同时写文字。

## 9. 功能明细与交互逻辑

### 9.1 连接服务器

页面只有地址输入框和「连接」按钮。占位文案为 `https://todo.example.com`。

| 操作结果 | 界面 |
|----------|------|
| 地址不是 HTTPS | 输入框下方提示「请填写 https 开头的地址」，不发请求 |
| 正在连接 | 按钮变为「连接中」，不可重复点击 |
| 健康检查成功且家庭未初始化 | 进入创建家庭 |
| 健康检查成功且家庭已初始化 | 进入登录；若本机已有未过期会话，直接进入今天 |
| 超过 10 秒没有响应 | 提示「连不上家庭服务器」，按钮恢复，可再试 |
| 证书或域名错误 | 提示「无法验证这个地址的安全连接」 |
| 返回内容不是本服务 | 提示「这个地址不是家庭待办服务」 |

「我的」里可以查看当前地址。点击「更换服务器」先确认「更换后需要重新登录」。确认后清除会话再回到连接页。皮肤和字号保留。

### 9.2 创建家庭与登录

创建家庭的字段：家庭名称、显示名、用户名、密码、确认密码。时区一行只读文字：「中国标准时间」。

校验：

- 家庭名称、显示名必填，1–20 字。
- 用户名 3–20 位，只允许小写字母和数字，家庭内唯一。
- 密码 6–64 位，两次输入必须一致。
- 任一校验失败时，对应字段下方显示原因，不提交。

登录字段是用户名和密码。失败时提示「账号或密码不正确」，不说明是哪一个错了。停用账号提示「账号已停用，请联系家庭管理员」。

本版没有自助找回密码。管理员可在成员页重置他人密码。管理员自己的密码在登录后于「我的」修改。管理员密码丢失时，在飞牛的服务器侧重置，不在手机里提供后门。

### 9.3 今天

打开应用后的第一屏。顶部是日期、一句「今天」和右上角头像。其下是按标题过滤的搜索框，只过滤本屏清单。

分组顺序固定：

1. **孩子今天**  
   仅管理员和家长可见，且家庭里至少有一个未停用的儿童、并存在进行中的计划时显示。每行是孩子显示名、计划标题、该孩子今天的状态文字。点击进入该计划详情。某个孩子今天没有要打的计划时，不单独占行。
2. **今日打卡**  
   我作为执行人、且今天有周期实例的进行中计划。待执行的行右侧是「打卡」。已完成的行显示反馈摘要。没有项时，这一组不占位。
3. **今日待办**  
   指派给我、且未完成的待办：截止日是今天、已过截止时间，或没有截止时间。已过截止时间的行标注「已过期」，不再响第二次。我已完成的待办不留在这里。
4. **接下来**  
   我参与的、开始时间在未来 48 小时内的日程，按开始时间排序，最多 3 条。更多的日程去日历看。

四个组都没有内容时，显示空状态：「今天还没有安排」，主按钮「写一条待办」。儿童的空状态按钮同样是「写一条待办」。

下拉刷新重新请求。请求失败时保留本次打开后已经看到的内容，并在顶部显示「暂时连不上家庭服务器」和「重试」。本次打开后还没有任何内容时，用整页错误和「重试」，不显示空白清单冒充成功。

### 9.4 新建菜单与表单共用规则

加号打开底部菜单，点选后进入对应的全屏表单。左上角「取消」直接返回，不保存。右上角「保存」提交。

保存成功：关闭表单，回到来源页并刷新，短提示说明结果，例如「已保存计划」。保存失败：表单保留已填内容，提示「没能保存，请重试」。

指定成员的选择器列出未停用成员。规则：

- 儿童新建时，执行人锁定为自己，选择器不出现。
- 成人不能勾选儿童。
- 家长和管理员可以勾选任何未停用成员。
- 至少保留一名执行人或参与人。日程和计划默认先勾上自己。

### 9.5 便签

列表按更新时间倒序。置顶的便签排在最前。每行显示标题、一行正文摘要、相对时间和可见范围。没有便签时显示「还没有便签」和「写一条」。

编辑字段：标题（必填，1–40 字）、正文（可空，最多 1000 字）、可见范围、置顶。

可见范围：

| 选项 | 谁能看 |
|------|--------|
| 仅自己 | 默认。只有作者 |
| 指定成员 | 作者加上被选中的成员 |
| 全家 | 所有未停用的成人、家长和管理员。儿童看不到，除非该儿童被单独指定 |

儿童只能选「仅自己」或「指定家长」。指定家长的列表里只有家长和管理员。

菜单中的「转为待办」打开待办表单，标题预填，执行人默认是自己。保存待办后，便签留在原处，详情底部出现「已关联待办」，点击可打开那条待办。

删除需要确认「删除这条便签？」。删除便签不删除已经转出的待办。

### 9.6 待办

字段：标题（必填，1–80 字）、补充说明（可空，最多 500 字）、截止时间（可空）、提醒（见 9.9）、执行人（至少一名）。

多名执行人时，每人一条完成状态，互不影响。只有执行人本人可以把自己的状态从未完成改为已完成，或改回未完成。其他人看到的是文字状态，不能代点。

详情按执行人列出状态。创建人、执行人可以编辑标题、时间和成员。儿童只能编辑自己创建的待办。从执行人中移除某人时，这个人的完成状态一并移除。

删除需要确认。创建人或管理员可以删除。

没有截止时间的待办一直留在执行人的「今日待办」里，直到本人完成。

### 9.7 日程

字段：标题（必填，1–80 字）、全天开关、开始、结束、参与人、提醒。

- 关闭全天时，结束时间必须晚于开始时间。
- 打开全天时，占用家庭时区的那一天，不再填写具体时刻。
- 参与人都能在日历和「接下来」里看到。
- 儿童可以成为参与人，从而在自己的日历里看到。儿童不能自己新建日程。
- 创建人、家长和管理员可以编辑和删除。删除需要确认「删除这个日程？」。

### 9.8 计划

列表有两个分段：「进行中」和「已归档」。卡片显示标题、周期原文、本周期每位执行人的显示名和状态文字。

谁能在列表里看到：

- 执行人本人。
- 创建人。
- 管理员和家长，当执行人里有儿童时。家长由此看到孩子的计划，即使自己不是执行人。

空状态：「还没有计划」。成人、家长、管理员看到「新建计划」。儿童没有这个按钮。

新建和编辑字段：

| 字段 | 规则 |
|------|------|
| 标题 | 必填，1–40 字 |
| 说明 | 可空，最多 500 字 |
| 周期 | 每天；每周至少选一个星期；每月选择 1–28 中的一天；每 N 天，N 为 2–30 |
| 开始日期 | 必填，不能晚于结束日期 |
| 结束日期 | 可空。空表示一直继续，直到归档 |
| 提醒时刻 | 可空。有值时，每个发生日的这个时刻响一次 |
| 执行人 | 至少一名 |

编辑周期或成员时，今天之前的执行记录不改写。新的周期从明天开始生效。今天已经生成的实例保持原样。

详情结构：

1. 标题、周期原文、提醒时刻、起止日期。
2. 「本周期」卡片。每个执行人一行：显示名、状态、反馈原文。若当前用户是执行人且今天的状态是待执行，底部固定主按钮「完成打卡」。
3. 「以往周期」清单，按日期从新到旧，每天展开后仍是每人一行。缺卡写「缺卡」，不提供补卡按钮。

「完成打卡」打开底部卡片：计划标题、可选反馈输入框、按钮「完成」。反馈最多 100 字，可以为空。成功后该行变为「已完成」，卡片关闭，短提示「已打卡」。失败则卡片保留文字并提示「没能保存，请重试」。

未来的周期实例出现在日历上，状态为「未开始」，不能打卡。当天 23:59 之后仍是待执行的记录，在下一次读取时变为缺卡。

创建人或管理员可以「归档计划」。确认文案：「归档后不再生成新的打卡，已有记录会保留」。归档后从「今天」和今后的日历中消失，留在「已归档」分段，详情只读。

### 9.9 提醒

每条待办、每个日程、每个计划各自最多一个提醒时刻。到点只响一次，错过不补响。

待办的提醒选项：

- 不提醒，这是默认。
- 截止时。没有截止时间时不可选。
- 提前 1 小时。没有截止时间时不可选。
- 自定义一个具体时间。自定义时间必须晚于当前时间，否则保存时提示「提醒时间要晚于现在」。

日程的提醒选项：

- 非全天：不提醒、开始时、提前 10 分钟、提前 1 小时。默认提前 10 分钟。
- 全天：不提醒、当天 09:00、提前一天 09:00。默认不提醒。

计划的提醒是发生日的一个钟点，例如 20:00。默认不提醒。

本地通知的登记规则：

- 用户允许通知后，每次事项同步成功，应用按当前账号重算这台手机上尚未触发的通知。
- 只登记触发时间还在未来的提醒，最近的优先，最多 60 条。
- 一条提醒对应一条通知。标题是事项标题。正文按类型写「待办」「日程」或「计划」。
- 点击通知打开对应详情。应用已退出时，先进入应用再打开详情。
- 待办通知只登记给执行人自己的手机。日程通知只登记给参与人。计划通知只登记给执行人，不登记给仅仅前来查看的家长。
- 同一人有多台手机时，每台手机各自登记，可能各响一次。

通知权限：

- 第一次同步到至少一条未来提醒时，再向系统申请权限。连接服务器和登录阶段不申请。
- 用户拒绝后，「今天」顶部出现条幅「提醒权限未开启」，按钮「去设置」。条幅可关闭，关闭后 7 天内不再出现。事项仍然保存，只是这台手机不会响。

证书失效或删除重装后，系统里已登记的通知不再可靠。用户重新签名安装、登录并同步成功后，应用重新登记尚未到期的提醒。这个行为写进「我的」底部的一行说明：「提醒保存在这台手机上。重新安装后，打开应用同步一次即可恢复未来的提醒。」

### 9.10 日历

月视图占上半屏。能左右切换月份，并有「今天」按钮回到本月且选中今天。有事项的日期显示一个强调色圆点，不按事项类型分色。

下半屏是选中日的分组清单：日程、待办、计划。日程显示时间范围或「全天」。待办显示本人的完成状态。计划显示本人的周期状态；家长在孩子的计划上看到的是自己有权查看的那一行，进入详情后看全员。

选中日没有任何可见事项时，显示「这一天还没有安排」。成人和家长看到「新建」，儿童不显示新建，因为儿童不能在日历里创建日程或计划。

### 9.11 成员、皮肤和密码

「我的」显示显示名、角色、用户名、当前皮肤、当前字号、服务器地址。

皮肤是三选一，字号是二选一，点选立即生效并记住。

管理员看到「成员」。列表显示显示名、用户名、角色和是否停用。添加成员时填写显示名、用户名、初始密码和角色。角色只有家长、成人、儿童，不能再创建管理员。

进入某个成员可以修改显示名和角色、重置密码、停用或恢复。不能停用自己，不能修改自己的角色，不能删除成员。停用后不能登录，历史打卡记录仍显示原显示名。

所有成员都可以修改自己的密码，字段为当前密码、新密码、确认新密码。管理员重置他人密码时不需要知道旧密码。

### 9.12 加载、空、错误和权限

- 列表第一次加载用三行骨架，不用大段说明文字。
- 空状态必须带有这个页面真正能做的下一步。没有权限做下一步时，只保留说明，不放一个点了也没用的按钮。
- 没有权限的入口直接不显示。若从通知打开了一条已经看不见的事项，显示「这条内容不存在或你没有权限」，按钮回到「今天」。
- 会话过期时回到登录页，并保留服务器地址。

## 11. 状态、规则与异常处理

| 场景 | 处理 |
|------|------|
| 计划有多名执行人 | 不存在「整个计划今天已完成」。每人单独一条状态 |
| 当天 23:59 前未打卡 | 次日读取时变为缺卡，不能改回完成 |
| 未来周期 | 日历可见，状态为未开始，没有打卡按钮 |
| 归档 | 停止生成新实例，历史保留，详情只读 |
| 停用成员 | 不能登录，不能被新事项选中；已有记录保留显示名 |
| 儿童查看范围 | 自己的便签和待办，自己参与的日程和计划。看不到「全家」便签，看不到他人事项 |
| 家长查看孩子 | 可以打开孩子作为执行人的计划并看到全部执行人状态。不能打开孩子的私人便签和孩子自己创建、且未指定家长的待办 |
| 成人查看孩子 | 不能因为对方是孩子就看到计划。成人自己创建的内容自己可见 |
| 代打卡 | 不允许。家长也不能替孩子点完成 |
| 提醒已过期才同步到手机 | 不补响，事项上仍然保存原来的提醒设置 |
| 通知条数超过 60 | 只保留最近的 60 条未来提醒 |
| 保存时网络中断 | 表单内容还在，提示重试 |
| 会话过期 | 回到登录 |
| 证书掉签或应用被删除 | 重新签名安装后登录同步，重新登记未来提醒 |

每月周期只用 1–28 日，避免 29–31 日在短月无法落点。需要「月底」时，本版用每月 28 日。

## 12. 原型页面清单

原型需要能走完第 7 节的流程，并带上第 10 节的示例数据。默认打开在林晨的「今天」，皮肤为夜航。

| 页面 | 必须能操作的结果 |
|------|------------------|
| 连接服务器 | 拒绝非 HTTPS；成功后按是否初始化进入创建或登录；失败可重试 |
| 创建家庭 | 校验失败停在表单；成功进入空的今天 |
| 登录 | 可切换林晨、周宁、林秀兰、林小满四个示例身份，看到的数据不同 |
| 今天 | 搜索、分组、空状态、连不上时的重试；家长能看到孩子今天 |
| 新建菜单 | 成人和家长四项，儿童两项 |
| 便签列表与编辑 | 新建、置顶、改可见范围、转待办、删除确认 |
| 待办表单与详情 | 多人状态各自独立，只能勾自己 |
| 日程表单 | 全天与非全天的时间校验，提醒选项随全天变化 |
| 日历 | 切换月份、选中日期、打开当天事项、空日期 |
| 计划列表 | 进行中与已归档切换 |

## 13. 验收标准

- [ ] 四个底部入口能切换，儿童登录后仍然是这四个入口，但看不到别人的事项。
- [ ] 林晨能看到林小满今天的阅读状态；林秀兰看不到这条计划；林小满看不到家长会和私人便签。
- [ ] 阅读计划里林小满和周宁的状态互不影响。林晨不能替林小满打卡。
- [ ] 打卡可以不写反馈，也可以写一句；超过 100 字不能保存。
- [ ] 过了当天的待执行记录表现为缺卡，没有补卡入口。
- [ ] 一条事项只能配置一个提醒，界面上没有「逾期再提醒」。
- [ ] 非 HTTPS 地址不能连接。连接失败有说明和重试。
- [ ] 创建家庭和登录的校验会停在字段旁，不会静默失败。
- [ ] 三套皮肤和两档字号能立即切换，底部导航和分组结构保持不变。
- [ ] 便签可以转成待办，原便签仍在，并能打开关联待办。
- [ ] 删除、归档、更换服务器、停用成员都有确认，确认后的结果能在列表里看到。
- [ ] 空列表、加载失败、没有权限三种状态的文案彼此不同。

## 14. 待确认问题

以下三项不改变本版页面结构，先按写入的规则执行：

1. 孩子的年龄段没有提供。本版按能够阅读短句的孩子设计，使用同一套布局和更大的默认字号。若孩子是学龄前，需要另议一版更少文字的界面。
2. 对外名称暂用 LuckyTodo。
3. 家庭时区固定为中国标准时间。这是本版假设。若有人长期不在这个时区，再增加时区设置。
