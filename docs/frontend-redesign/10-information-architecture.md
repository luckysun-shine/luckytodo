# 10 信息架构

本规格覆盖 `redesign-recommendations.md` 里「手机五栏、家庭作为二级页」的建议。对齐对象是 v005「首页 / 待办 / 计划 / 日历 / 便签 / 家庭」，以及当前已经落地的模块，而不是另做一套业务。

Figma 文件 `uwS6F2XKfZdCwMCa3jmBfy` 的画板对照沿用 v005 第 6 节。布局以仓库里的页面函数为准，视觉 token 以 `13-design-tokens.md` 为准。日间品牌色保持 logo 同系的青绿 `#4EB7AC`。夜间与纸色的 `[data-theme]` 选择器保留。

已确认（2026-10-09）：

1. 日间青绿与 logo 统一，不改成蓝色。夜间、纸色选择器保留。
2. 深链 `me` 与 `family` 都进入家庭页。
3. 添加在顶栏，底栏不为 FAB 留空。儿童添加菜单只有便签和待办。
4. 完成与撤销只改 `completions`，勾选后 5 秒内可撤销。无积分、排行或新字段。
5. 便签转待办仍是新建待办，原便签保留。
6. 计划编辑和归档使用现有 payload 与 `archived`，保存同一 id。不增加重复待办引擎。
7. 邀请只给管理员和家长。儿童账号用应用内表单。
8. 界面不出现远程推送、成长积分、排行榜、清单 Tab。本机提醒和打卡热力保留。`admin.html` 仍在浏览器配置模型。

第 4、6、7 条的交互改造在壳层之后单独做。本轮壳层已接上第 2、3、8 条里「推送入口不出现」。

## 1. 谁在用

角色与服务端 `visibleTo`（`apps/api/src/index.js`）一致，界面不新增角色。

| 角色 | 代码值 | 能做的主操作 |
| --- | --- | --- |
| 管理员 | `admin` | 邀请、创建儿童、导出、注销、手动刷新洞察、处理冲突 |
| 家长 | `parent` | 邀请、创建儿童、看家庭内待办与打卡、手动刷新洞察 |
| 成人 | `adult` | 便签、待办、日程、计划；执行被指派的事项 |
| 儿童 | `child` | 便签、待办；不能新建日程或计划（`openCreateForm` 已拦截） |

拉取同步时服务端已按可见性过滤。界面只展示本机 IndexedDB 里的记录，不在客户端再发明一套权限模型。

## 2. 六个主 Tab

底栏六项，顺序固定。业务分支仍是现在的 `bodyMap`，只把家庭从「头像二级页」升回主 Tab。

| 顺序 | 名称 | `state.tab` | 现有模块 | Figma nodeId |
| --- | --- | --- | --- | --- |
| 1 | 首页 | `home` | `renderHomeBody` | `43:9` |
| 2 | 待办 | `todo` | `renderTodoBody` | `43:111` |
| 3 | 计划 | `plans` | `renderPlansBody`；详情 `renderPlanDetail` | `43:345` |
| 4 | 日历 | `cal` | `renderCalBody` | `43:180` |
| 5 | 便签 | `notes` | `renderNotesBody` | `43:292` |
| 6 | 家庭 | `family` | 今天的 `renderMeBody`（成员、邀请、儿童、共享待办、动态、设置） | `43:424` |

兼容：深链和旧状态里的 `me`、`family` 都进入家庭 Tab；`today` 仍进入首页。`tabs()` 今天只有五项，注释写明个人中心改由头像进入。改造时改的是 `tabs()` 与 `renderHome` 的标题表，不是新的同步类型。

洞察不是第七个 Tab。入口留在首页洞察卡，页面仍是 `renderInsightsBody`。v003 曾把洞察放进底栏；v005 的六 Tab 不含洞察，本规格跟随 v005 和本次任务列表。

`renderTodayBody` 无调用，不进入信息架构。

## 3. 屏幕层级

认证和家庭门是全屏，不显示底栏。

```text
启动闪屏
  → 未登录：登录 ↔ 注册
  → 已登录无家庭：创建家庭 | 加入家庭
  → 有本机待并入记录：合并确认
  → 主壳（六 Tab）
        首页 ── 洞察（二级）
        待办 ── 待办编辑
        计划 ── 计划详情 ── 打卡 / 计划编辑
        日历 ── 当日事项 ── 日程或待办编辑 / 计划详情
        便签 ── 便签编辑 ── 转待办
        家庭 ── 邀请码 / 儿童账号 / 头像裁剪 / 冲突列表 / 注销确认
  全局：添加菜单 → 便签 | 待办 | 日程 | 计划
```

添加按钮在顶栏右侧，不占用底栏格子，也不再压住第六个 Tab。儿童的添加菜单只有便签和待办。

计划详情、编辑表单、洞察、邀请码、裁剪、确认框叠在当前 Tab 之上。切换 Tab 不压入返回栈；叠层才压栈。栈空时系统返回才离开应用。这条与 `native.js` 里「没有历史就 `exitApp`」的现状不同，实现见 `12-interaction-specifications.md`。

## 4. 全局入口必须保留

视觉重做时这些入口仍在，位置可以换，不能消失。

| 入口 | 今天在哪 | 新位置 |
| --- | --- | --- |
| 搜索 | 首页、待办；便签只吃同一个 `state.query` | 各页自己的搜索，互不清空对方 |
| 添加 | 右下角 FAB `openCreateSheet` | 主壳顶栏「添加」 |
| 同步 | 家庭页「立即同步」；在线/离线事件 `maybeSync` | 家庭页保留；离线横幅仍在主壳顶部 |
| 洞察 | 首页卡与 `state.tab = insights` | 首页卡进入二级页 |
| 邀请 | 家庭页，角色 `admin`/`parent` | 仍只对这些角色显示 |
| 导出、冲突、注销、退出 | `renderMeBody` 设置卡 | 家庭页「设置与数据」 |
| 协议 | 登录页链接 `terms.html`、`privacy.html` | 登录与注册都链接这两页 |
| 主屏组件 | `widgetBridge`，不在 Tab 内 | 不改快照字段 |

忘记密码今天是一个只会 toast 的按钮，没有重置接口。规格把它改成说明文字：「请让家庭管理员协助，或注册新号码后再用邀请码加入。」不做成可点击的假流程。

推送登记今天写入占位 token。家庭页不再出现「已开启推送」开关。本地提醒仍由 `reminders.reschedule` 调度，文案写「本机提醒」，不写远程推送。

成长感来自连续打卡天数、计划热力和里程碑进度。这些都使用已有的 `checkin` 与 `milestones`。不增加积分、等级、排行榜。

计划表单里的每天/每周/每月/间隔是已有字段 `cycle`、`weekdays`、`monthDay`、`interval`，不是新的重复待办引擎。待办没有重复规则字段，界面不提供「重复待办」。

`list` 与 `attachment_meta` 服务端允许同步，前端没有创建界面。信息架构不新增「清单」Tab。

## 5. 对象到页面

| 实体 `entityType` | 写入 | 主要阅读位置 |
| --- | --- | --- |
| `note` | 便签表单 | 便签 Tab、首页最近便签、日历当日 |
| `todo` | 待办表单；便签转待办另建一条 | 待办 Tab、首页今日待办、家庭共享待办、日历 |
| `event` | 日程表单 | 日历、首页「今日日程」计数 |
| `plan` | 计划表单 | 计划 Tab、首页项目、详情页 |
| `checkin` | 打卡面板 | 计划详情、首页连续天数、日历、热力 |

存储仍是 `db.js` 的 `luckytodo-v1` 与 `api.saveLocalEntity`。本信息架构不升数据库版本，不改 API 路径。
