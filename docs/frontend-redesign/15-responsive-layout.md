# 15 响应式布局

一套页面函数服务所有宽度。分叉只发生在壳：底栏或侧栏、抽屉贴底或居中、计划详情全屏或右栏。`renderTodoBody` 等不按桌面复制一份。

今天 `#app { max-width: 430px }`，唯一 `@media` 是减少动效。本规格取消这道锁，改为下面的断点。

## 1. 断点

| 名称 | 条件 | 壳 |
| --- | --- | --- |
| 手机 | 默认，直到 959px | 单列；底栏六 Tab；添加在顶栏；详情与表单全屏 |
| 平板 | `min-width: 960px` | 左侧栏六项，宽度 220px；底栏隐藏；内容占满剩余宽度；详情仍全屏盖住内容区 |
| 桌面 | `min-width: 1200px` | 侧栏 + 列表 + 详情栏。详情栏宽 `minmax(360px, 420px)`。计划从列表点选时写 `planId`，右栏渲染 `renderPlanDetail` 的内容区，不把整页 `screen` 换成独占层 |

900px 以下表单全屏（现有 `.form-screen`）。960px 起表单为内容区上的对话框：宽 `min(640px, 100% - 48px)`，最大高度 `min(88dvh, 800px)`，内部滚动。

认证页在手机上通栏留 `--space-4`；宽于 960px 时卡片 `max-width: 420px` 水平居中，背景仍是整页 `--bg`，不再把整个应用锁成手机模型。

PWA `manifest.webmanifest` 的 `orientation` 今天是 `portrait-primary`。桌面安装后若要横屏，改为不锁定方向。原生 App 的竖屏偏好仍由 Capacitor / Android 配置决定，Web 布局不依赖它。

## 2. 区域

```text
手机
┌──────────────────┐
│ 顶栏：标题    添加 │
│ 离线横幅          │
│ 滚动内容          │
│ 底栏六项          │
└──────────────────┘

桌面 ≥1200px
┌────┬────────────┬─────────┐
│侧栏│ 当前 Tab 列表 │ 详情     │
│    │            │ 无选中时  │
│    │            │ 显示当日  │
└────┴────────────┴─────────┘
```

右栏无 `planId` 时显示日历选中日或今天的事项摘要，数据与 `renderCalBody` 的当日列表相同，不另写查询。从待办、便签、家庭 Tab 看右栏时，右栏保持最近打开的计划；没有则显示当日事项。不在右栏放第二套编辑器。

手机上的计划详情是压栈全屏。桌面点列表只替换右栏，浏览器后退清除 `planId`。两种都调用同一详情函数。

侧栏项与底栏项同一数组：首页、待办、计划、日历、便签、家庭。选中态同一 `state.tab`。

## 3. 安全区与键盘

`index.html` 已有 `viewport-fit=cover`。

| 变量 | 来源 |
| --- | --- |
| `--safe-top` | `env(safe-area-inset-top)` |
| `--safe-bottom` | `env(safe-area-inset-bottom)` |
| `--keyboard-inset` | `visualViewport` 高度差，非键盘时为 0 |

顶栏 padding-top 使用 `--safe-top`。底栏 padding-bottom 使用 `--safe-bottom`。全屏表单的主按钮 margin-bottom 使用 `max(--safe-bottom, --keyboard-inset)` 的空间，避免按钮落在键盘下。

Android 清单已是 `adjustResize`。`100dvh` 在部分 WebView 不随键盘缩小，所以才记 `--keyboard-inset`。没有真机时，桌面浏览器用开发工具设备模式只能验证安全区变量是否写入，不能当作键盘已通过。

裁剪层继续挂在 `document.body`，自身 padding 含 `--safe-bottom`，宽屏也居中，圆框保持 280px。

## 4. 日历与列表在宽屏

手机日历可收起，状态仍写入 `lt_cal_expanded`。`min-width: 960px` 时忽略收起，月历与当日列表左右并排：月历约 360px，列表占余下宽度。手势监听可以保留，但不改变宽屏的并排。

待办、便签、计划列表在桌面单列阅读宽度最多 720px，靠在内容区左侧，不拉成超宽行。右栏存在时列表区已经变窄，不再额外限宽。

首页四格统计：手机 2×2，`min-width: 720px` 时一行四格。项目卡在内容区宽于 800px 且没有右栏时两列，有右栏时一列。

## 5. 触控与指针

点按目标不小于 44×44。桌面悬停只改变背景到 `--field`，不依赖悬停才能发现按钮。`prefers-reduced-motion` 已全局缩短动画。

六个中文标签在 320px 逻辑宽度下仍须完整显示（每项两字）。不允许底栏横向滚动。若与系统字体放大冲突，优先保证图标可点，标签允许省略号，这是唯一的截断。

## 6. 落地对照

| 项 | 内容 |
| --- | --- |
| 对应模块 | `#app` 宽度、`.tabs`、`.form-screen`、`.modal`、`renderHome` 壳、`renderCalBody`、`renderPlanDetail` |
| 改动文件 | 首批只改 `styles.js` 的 `#app` 最大宽度与安全区变量。侧栏、右栏、键盘 inset 在页面拆分之后，避免绝对定位的表单被拉满窗口 |
| 数据层 | 不影响。`planId` 仍是界面状态 |
| 验证 | 390px 宽：六 Tab、添加在顶栏、表单全屏。1000px：侧栏出现、底栏消失、认证卡片居中。1280px：计划列表与详情同时可见，勾选待办仍更新列表。刷新后 Tab 恢复属于导航批次，不作为纯 CSS 批次的验收 |

## 7. 与实现顺序的关系

1. 日间 token 保持青绿，先做六 Tab 与顶栏添加。`#app` 的 430px 列宽留到侧栏批次再打开，避免六栏在宽屏被拉成整条。
2. 再把底栏改成六项、添加移到顶栏。此步改 `tabs()`，仍是单列。
3. 导航栈与刷新恢复。
4. 表单编辑、撤销 toast、邀请抽屉、打卡抽屉。
5. 最后做 960 / 1200 的侧栏和右栏。

第 5 步之前，宽屏只要求满宽不破版、主路径可点，不要求三栏。
