# 12 交互规格

交互只描述已经存在的数据行为，或把已有字段补到界面上。完成、撤销、转待办、计划编辑、邀请都不新增实体类型。

栈规则：Tab 切换替换当前历史条目；打开详情、表单、菜单、确认框时压栈；返回弹出一层。实现落在后来的 `nav` 与 `native.js` `backButton`。在该实现落地前，页内返回按钮必须仍能关闭当前层。

## 1. 任务完成与撤销

对应 `todoCard` 的勾选。数据是 `payload.completions[memberId]`：`done` 或 `open`。每个成员只改自己的键。

完成：

1. 勾选。
2. `saveLocalEntity('todo', { ...payload, completions }, { id })`。
3. 原生上 `lightTap()`。
4. Toast「已完成」，带文字按钮「撤销」，5 秒后消失。
5. 家庭模式随后 `maybeSync()`。行上仍可出现「待同步」。

撤销：

1. 5 秒内点「撤销」，或在「已完成」里再点一次勾选。
2. 同一 id，把该成员的值写回 `open`。
3. Toast「已恢复为未完成」。不再提供第二次撤销倒计时。

勾选失败时恢复勾选外观并 toast 错误。不使用积分、连击或音效。连续打卡天数不因待办完成而增加，它只数 `checkin.status === 'done'`。

| 落地 | |
| --- | --- |
| 文件 | `app.js` `todoCard`、`toast` |
| 数据层 | 只更新 `completions`。不新字段 |
| 验证 | 完成后再撤销，筛选计数回到未完成；另一成员的 `completions` 不被覆盖；飞行模式仍能勾选，联网后队列被推送 |

## 2. 便签转待办

对应 `renderNotesBody` 里已有的转换。

1. 在便签上点「转待办」。
2. 新建 `todo`：`title` 用便签标题，`notes` 用正文，`dueAt` 空，`reminderKind` `none`，`assigneeIds` 为当前成员，`priority` `medium`，`attachmentIds` 复制便签已有 id。
3. 原便签保留，含置顶和可见范围。
4. Toast「已转为待办，便签仍保留」，动作「去查看」切到待办 Tab。
5. 不自动删除、不自动归档便签。

标题为空时按钮不可用。

| 落地 | |
| --- | --- |
| 文件 | `renderNotesBody` |
| 数据层 | 新增一条 todo。便签 id 不变 |
| 验证 | 转换后两条都在；待办执行人是当前成员；再次转换会再增一条，界面不合并 |

## 3. 计划编辑

今天 `renderPlanForm` 只用于新建，`archived` 恒为 `false`。详情不能改标题和周期。

编辑入口：计划详情顶栏「编辑」。打开同一表单，草稿从 payload 填入：`title`、`notes`、`cycle`、`weekdays`、`monthDay`、`interval`、开始结束、`reminder`、`executorIds`、`milestones`、附件 id。

保存：`saveLocalEntity('plan', nextPayload, { id: plan.id })`。里程碑 id 保持不变，避免打卡和提醒对不上。新增的里程碑用 `db.uuid()`。

归档：详情上的「归档」先确认「归档后首页不再展示，打卡记录仍保留」。确认后 `archived: true`。已归档详情提供「恢复」，写回 `false`。筛选「已归档」因此才有数据。

儿童没有编辑和归档。家长与管理员可以打开自己可见的计划；保存仍走同一同步队列，权限冲突由服务端同步结果处理，界面不假装本地一定成功。

周期控件只编辑已有枚举：`daily`、`weekly`、`monthly`、`interval`。不出现 RRULE、不把周期抄到待办上。

| 落地 | |
| --- | --- |
| 文件 | `renderPlanForm`、`renderPlanDetail`、`defaultDraft` |
| 数据层 | 同一计划 id 的 payload 更新。无新 API |
| 验证 | 改标题后列表与详情一致；归档后首页项目消失、归档筛选出现；里程碑完成状态还在 |

## 4. 家庭邀请

对应 `renderMeBody` 邀请按钮与 `api.createInvite('adult')`。

可见角色：`admin`、`parent`。成人和儿童不渲染该按钮。

1. 点「邀请成员」。
2. 请求进行时按钮为「生成中…」并禁用。
3. 成功后打开抽屉：6 位邀请码、复制、说明「把邀请码发给家人，在加入家庭里填写」。
4. 复制成功 toast「已复制」。剪贴板失败时邀请码仍留在抽屉里，可长按选择。
5. 失败 toast 服务端 `error` 文案，不展示空码。

加入侧在家庭门，调用 `acceptInvite`。码无效时停留家庭门并 toast。

儿童账号不是邀请流程。管理员或家长点「添加儿童」，打开表单：显示名、密码（至少 6 位）。提交 `createChild`。成功 toast 显示返回的登录名，并刷新成员。密码框使用应用内字段，不再用 `prompt`。

| 落地 | |
| --- | --- |
| 文件 | `renderMeBody`、`renderFamilyGate` |
| 数据层 | 不影响协议。仍是 `/api/invites` 与 `/api/members/child` |
| 验证 | 成人账号无邀请按钮；生成的码能在第二账号加入；儿童创建后成员列表出现，且该儿童不能看到邀请按钮 |

## 5. 打卡

对应 `checkin.js` 与计划详情。替换 `prompt` / `confirm`。

抽屉「今日打卡」：可选一句反馈（可空）、可选照片、主按钮「完成打卡」。照片按钮在同一次点击里打开 `<input type="file" accept="image/*">`，避免异步对话框丢掉用户手势。

保存 `checkin`：`planId`、`memberId`、`date`（当天 `dayKey`）、`status: 'done'`、`feedback`、`photoMediaId`。成功后关抽屉、toast「打卡成功」、刷新连续天数与热力。

取消不写记录。上传失败时保留已输入的反馈，照片为空，toast 错误。

| 落地 | |
| --- | --- |
| 文件 | `apps/web/src/checkin.js`、`renderPlanDetail` |
| 数据层 | 仍是一条 `checkin`。照片走现有 `uploadMedia` |
| 验证 | 不附照片也能打卡；附照片后详情或日历能看到这条打卡；取消后条数不变 |

## 6. 确认、同步与冲突

破坏性动作使用确认框，不用 `window.confirm`。

| 动作 | 标题与后果 | 确认按钮 |
| --- | --- | --- |
| 清空本机离线记录 | 不可恢复 | 清空 |
| 归档计划 | 首页不再展示，记录保留 | 归档 |
| 注销账号 | 不可恢复，登录凭证失效 | 注销 |
| 退出登录 | 本机会话清除，未推送的队列仍留在本机库 | 退出 |
| 软删除一条记录 | 家人同步后也会消失 | 删除 |

软删除使用已有参数 `saveLocalEntity(type, payload, { id, deletedAt })`。入口放在编辑页底部。创建者可删自己创建的便签、待办、日程、计划。管理员可删家庭内这些记录。儿童不提供删除。本规格不增加回收站。

冲突：家庭页进入列表，而不是只处理 `conflicts[0]`。每一条两个动作：「用服务器版本」「保留我的并上传」，对应 `resolveConflict(id, 'server' | 'mine')`。没有冲突时设置行 toast「当前没有冲突」。

立即同步：成功 toast「已同步」，并更新「已同步 · 时间」。失败 toast 消息。离线时家庭页写「当前离线，改动会在联网后同步」，按钮仍可点，失败沿用网络错误文案。

| 落地 | |
| --- | --- |
| 文件 | `renderMeBody`、`renderMerge`、表单、`api.resolveConflict` 的调用处 |
| 数据层 | 删除与冲突都走现有队列。不改 `db.js` 版本 |
| 验证 | 注销前可取消；冲突两条可分别选择；删除后本机列表消失且队列含 `deletedAt` |

## 7. 表单与键盘

- 打开编辑时填值；打开新建时用 `defaultDraft`。
- 切换执行人或可见范围时保持滚动位置和当前焦点，沿用 `draftPatch` 的意图；实现上避免整页重建输入框。
- 主按钮在滚动区底部，并留出安全区与键盘 inset（见响应式文档）。
- 第一个错误字段获得焦点。
- Escape 关闭添加菜单和确认框；全屏表单只认返回，避免误关丢掉草稿。
- 添加菜单点遮罩关闭。

## 8. 加载、空、错误

| 状态 | 表现 |
| --- | --- |
| 启动 | 闪屏，直到 `hideBootSplash` |
| 同步按钮、邀请、保存 | 按钮禁用，文案改为进行时 |
| 洞察请求中 | 卡片内一行「正在读取洞察」，失败后换成错误说明加本机规则 |
| 列表空 | `emptyState`：标题、一句说明、一个主动作（若该角色允许创建） |
| 搜索无结果 | 标题「没有匹配的…」，无创建按钮 |
| 页面渲染异常 | 现有「页面加载失败」与重新加载 |
| 行内校验 | 字段下 `.err`，颜色用 `--miss` |

列表不使用整页骨架屏。本应用的列表来自本地库，打开即可算完。只有洞察和媒体上传需要过程状态。

## 9. 搜索与刷新

`state.query` 拆成各页字段：`homeQuery`、`todoQuery`、`noteQuery`。切换 Tab 保留各自关键词。

浏览器刷新应恢复 `tab` 与 `planId`（导航实现之后）。刷新不恢复未保存草稿。令牌不进入 URL。

下拉刷新不是现有能力。本规格不新增下拉刷新库。家庭页的「立即同步」就是刷新动作。
